# 组织第二大脑：安装与使用手册

适用版本：AMH 1.4.10。面向 macOS 成员；试点组织 linkcrux，组织地址 `https://platform.linkcrux.com`。核对日期：2026-11-04。

## 一、你能用它做什么

把 Claude Code、Codex CLI、Claude Cowork、Codex 桌面本地模式产生的原生记忆共享给团队。换产品、换设备或换成员后，可以围绕当前问题找回已有经验，并看到生产成员和来源产品。

你仍在原来的产品里工作。产品负责生成记忆，AMH 负责后台同步和组织检索。说过一句话不等于产品已保存长期记忆；聊天记录与长期记忆也是不同的来源类型。

本次实测包含名为 ChatGPT 的桌面应用里的**本地 Codex 模式**，不代表普通 ChatGPT 聊天或云端 Work 支持本地 Hooks。Windows／Linux 不属于本手册的实机验收范围。

## 二、准备工作

1. 准备 Mac，安装并登录你要使用的产品。
2. 准备所属企业的飞书账号；管理员须已发布应用，并将你加入应用可用范围。
3. 确保能访问 GitHub、Python 软件包源和组织地址。
4. 安装 Python 3.11 或更新版本。安装器依次检查 `python3.13`、`python3.12`、`python3.11`、`python3`。可在终端用 `python3 --version` 查看默认版本；没有受支持版本时，先安装 Python 再重新打开终端。

**不需要邀请码，不需要服务器账号或密码。** 飞书登录自动确定成员身份与名称。

如果已有旧 AMH：旧记忆库保留，但组织版会停用所选产品中识别到的旧 AMH Hook、部分 MCP 和记忆纪律区块，避免重复注入。两套数据独立，接入配置不是完全互不影响。

## 三、从安装入口开始

先正常结束正在运行的 AI 任务。按 `Command + 空格`，搜索“终端”并打开。完整复制下面一条命令执行：

```bash
curl -fsSL https://github.com/liuyang0508/agent-memory-hub/releases/latest/download/install.sh | sh -s -- --org-memory --hub https://platform.linkcrux.com
```

已接入旧 `aihub0508.com` 的设备，请按[双 Hub 切换说明](dual-hub.zh.md)保留旧同步状态、独立登记新连接，不要直接修改旧配置里的 Hub 地址。

保留 `--org-memory`；省略它会进入旧 AMH 的安装流程。不需要 `sudo`。下载期间等待输出，不要反复启动安装。

需要固定安装本手册版本时，用下面这条代替：

```bash
curl -fsSL https://github.com/liuyang0508/agent-memory-hub/releases/download/v1.4.10/install.sh | sh -s -- --org-memory --hub https://platform.linkcrux.com
```

其他组织把最后的地址替换为管理员提供的 HTTPS 地址，不要填邮箱、账号或 SSH 地址。

### 通过 SSH 安装到另一台 Mac

远端需要 Python 3.11+，以及已安装并登录的 Codex CLI 或 Claude Code。飞书授权在你本机浏览器完成，不需要在远端登录飞书，也不要复制另一台设备的登录配置。

1. **你本机另开一个终端**，建立转发并保持运行：

   ```bash
   ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8765:127.0.0.1:8765 <你的SSH别名>
   ```

   如果使用 `remote-claude`，可改用 `remote-claude forward 8765`；配置了多个连接时，使用 `remote-claude forward <别名> 8765`。

2. **在远端 SSH 终端**执行：

   ```bash
   curl -fsSL https://github.com/liuyang0508/agent-memory-hub/releases/latest/download/install.sh | sh -s -- --org-memory --hub https://platform.linkcrux.com --ssh
   ```

3. 安装器提示端口转发已启动时按回车。看到授权提示后，在**本机浏览器**打开 `http://127.0.0.1:8765/`，按飞书页面完成授权。
4. 远端终端进入“选择历史”后，再打开同一个地址，选择远端设备上的历史文件或跳过；回到远端终端完成产品接入确认。没有历史文件时会直接进入接入步骤。
5. 看到配置完成及后台服务登记结果后，可关闭转发终端。日常同步直接连接组织服务，不依赖这条转发。

通过 SSH 登录时会自动识别上述模式，`--ssh` 用于明确指定；`--no-ssh` 可恢复远端本机浏览器模式。端口被占用时，选择同一个新端口，例如转发 `8080:8080` 并在安装命令末尾加 `--web-port 8080`。**本机和远端端口必须相同**，不能使用 `8080:8765`，飞书回调会使用设置的端口。

超时后重新执行安装命令并打开新的授权页面。已成功登记的身份会复用，无需删除目录。稍后补选历史可在远端运行 `amh-native import --ssh`。SSH 安装使用 macOS 用户后台域，不要求桌面登录；如果后台服务启动失败，安装器会明确报错并以非零状态退出。Cowork 插件仍需在远端 Cowork 界面导入，SSH 模式不会自动打开远端 Finder 或浏览器。

## 四、飞书登录加入组织

1. 安装器下载软件并先检查组织服务能力；管理员需要先升级 Hub。检查通过后显示产品检测结果并打开浏览器。
2. 在飞书页面核对企业、账号与应用。本试点应用名称为“多智能体共享组织第二大脑”。
3. 按正常流程登录并授权。
4. 浏览器提示成功后回到终端，核对成员名称、稳定成员 ID 和组织。

不要转发密码、验证码、回调地址或配置文件。另一台机器用同一飞书账号登录，即是同一成员的另一台设备。

如果显示“已使用现有身份”，说明该目录已有登录状态，不是首次登录。不要为重试登录而删除产品记忆目录。

## 五、选择已有历史

安装器会打开“选择要共享的记忆”页面，通常是 `http://127.0.0.1:` 开头的本机地址；预览本身不会先上传所有历史。

- 新设备默认仅共享原生记忆。首次体验可跳过新增历史选择，先用一条虚构记忆跑通。已有设备的旧选择会保留，页面会说明当前范围。
- 需要导入时，按产品、类型、文件名或修改时间筛选，逐项勾选，再点 **“确认并继续”**。
- 聊天、规则、技能和配置需要额外确认启用；确认某类历史文件时，也会说明该类后续新增内容的共享范围。含密钥的文件不可选，带隐私标签的文件需自行决定是否共享；列表筛选不会自动撤销隐藏项的勾选。
- 确认后，终端显示本地全文检查进度；新发现的隐私、密钥或已变更文件会跳过。此阶段尚未上传。

**选择上传后，本组织成员可以检索正文。** 无法证明原作者的历史标注为未知，不因你上传就认定你是生产者。

未选历史及其后续改写不会仅因修改就自动变成可上传的新记忆，需要时重新导入。接入后，已绑定来源中的新增内容走自动共享。

## 六、确认产品接入

回到终端，对检测到的产品逐项回答。`[Y/n]` 中回车表示同意，不接入则输入 `n` 后回车。

最后出现 **“确认配置并启用？”** 时，核对后输入 `y` 并回车。这一步配置 Hook，并显示首次同步进度，随后启动后台服务。上传计数按云端已确认的内容条目推进，不等同于文件数量；一个较长文件可能拆为多项。

首次同步完成会显示“待上传 0 项”；失败时保留待上传内容并提示重试，不会把配置完成当成上传完成。检测到 Cowork 时会准备插件包，继续按下一节完成导入。

Claude Code、Codex CLI 和桌面本地 Codex 请**新建会话**。旧会话可能保留旧上下文。如产品要求 Hook 审核，核对 AMH 来源后使用产品正常的批准流程。

升级已有设备时，可运行 `amh-native scope` 查看范围；需要收紧为仅记忆时运行 `amh-native scope --kind memory` 并确认。调整范围会等待正在执行的整轮上传结束，不撤回已上传内容。

CLI 和桌面共用的文件可能标为 `codex`：这表示无法从同一份文件证明具体入口，不代表另一个成员。

## 七、接入 Claude Cowork

1. 安装器会在 Finder 定位 `cowork-plugin.zip`，默认位于 `~/.amh-native-sync/cowork-plugin.zip`。
2. 打开 Claude 桌面应用，进入 **Customize → Plugins → Add plugin → Upload**。
3. 选择刚生成的 ZIP，完成导入；已有同名插件时，核对后选择替换。
4. 确认 **Amh native org** 已启用，版本为 1.4.10。本机绑定的插件还提供组织只读 MCP 工具；在新任务中使用。

文件选择窗口看不到隐藏目录时，按 **Command + Shift + G**，粘贴终端显示的 ZIP 完整路径，再按回车和“打开”。无需解压。
5. 在 Cowork 新建任务，触发首次配对。

安装器把连接文件单独保存在本机私有目录，不需要贴给模型或放进插件 ZIP。首次票据 **7 天内单次有效**，配对成功后不需要每 7 天重新登录。每台机器各自生成插件，不把绑定本机路径的包直接给同事使用。

首次配对前票据已过期时，执行：

```bash
"$HOME/.local/bin/amh-native" cowork-connect --state "$HOME/.amh-native-sync" --output "$HOME/.amh-native-sync/cowork-plugin" --connection-dir "$HOME/.amh-native-sync/cowork-connection" --runtime-state "$HOME/.amh-native-sync/cowork-runtime"
```

Hub、成员和路径不变时，无需仅为刷新票据重新导入插件。首次导入仍要完成。

## 八、检查安装结果

查看主客户端状态：

```bash
"$HOME/.local/bin/amh-native" status
```

看 `hub` 是否正确、`identity` 是否为本人、`sources` 是否有共享来源、`pending` 是否逐步下降、`worker` 是否有近期同步记录。命令存在不等于四端全部成功。

Cowork 执行过首次任务后，再检查其独立运行时：

```bash
"$HOME/.local/bin/amh-native" status --state "$HOME/.amh-native-sync/cowork-runtime"
```

应与主客户端是同一成员、不同设备。未登记时，先核对插件启用状态与首次任务。

检查版本，本文版本应输出 `1.4.10`：

```bash
"$HOME/.amh-native/venv/bin/python" -c 'from importlib.metadata import version; print(version("agent-memory-hub"))'
```

本文使用完整命令路径，不要求新用户先配置 PATH。

## 九、第一次跨产品使用

每轮使用一个新的虚构项目名，避免已有对话包含答案而误判。

**先在 Claude Code 新建会话，发送：**

> 这是一条组织第二大脑的虚构验收资料，不是真实业务：测试项目“团队记忆体验-1102-A”的评审规则是“至少两位成员复核，验收标记为纸鸢47”。请按你当前产品允许的原生长期记忆写入方式保存，并告诉我实际保存路径。不要修改系统规则或项目代码；无法保存时请明确说明。

确认实际完成写入，只说“记住了”不算。新项目首次发现的文件若被识别为历史，可通过下一节的导入操作选择它。

等待后台同步；也可主动执行一次同步和查询：

```bash
"$HOME/.local/bin/amh-native" sync
"$HOME/.local/bin/amh-native" search '团队记忆体验-1102-A'
```

云检索能看到内容后，在 **Codex CLI 或桌面本地 Codex 的新会话**中发送：

> 测试项目“团队记忆体验-1102-A”的评审规则和验收标记是什么？请根据本轮提供的组织资料回答，并说明生产成员和来源产品。不要访问网络、读取本地文件、调用工具或保存新记忆。没有资料就说未召回，不要猜。

读取问题不包含答案。正确返回规则、标记和来源，才说明这一方向通过。再用同样问题在 Cowork 新任务中读取。反向验证时，让另一产品保存一个新的项目标识与事实，再回到 Claude Code 新会话提问。

日常直接自然语言提问即可，`search` 只是排查工具，不需要每次手动执行。产品是否生成长期记忆仍受自身功能、权限和生成时序约束。

## 十、日常共享、补导入与原生读取

当前问题触发组织检索，后台异步上传产品实际生成的内容。默认本组织所有成员可检索所有项目，项目标签不是权限隔离。生产成员和上传成员分别记录；他人的资料不会自动成为你的个人偏好或执行指令。

以后补选历史：

```bash
"$HOME/.local/bin/amh-native" import
```

只看记忆，或筛选时间：

```bash
"$HOME/.local/bin/amh-native" import --kind memory
"$HOME/.local/bin/amh-native" import --since 2026-11-01
```

选择后需在终端确认同步；文件在预览后变更会被拒绝，重新预览即可。

默认 AMH 不持久缓存组织正文。断网时无法云端召回，产品自己的本地记忆仍按原机制读取。网络超时会跳过组织召回而继续当前任务，不保证每次问题都命中。

希望组织记忆同时成为本地原生资源时，可明确选择：

```bash
"$HOME/.local/bin/amh-native" setup --hub https://platform.linkcrux.com --projection
```

这会重新走向导，并允许本机保存组织正文副本。共享规则、技能和配置也不等于自动激活，应用这些资产需明确选择，进阶操作见同目录 README。

## 十一、暂停、恢复、升级与卸载

暂停主客户端：

```bash
"$HOME/.local/bin/amh-native" pause
```

使用 Cowork 时也单独暂停其运行时：

```bash
"$HOME/.local/bin/amh-native" pause --state "$HOME/.amh-native-sync/cowork-runtime"
```

恢复时将相应命令中的 `pause` 改成 `resume`。暂停不删除原生记忆，也不撤回云端已上传内容。

卸载接入：先正常结束任务并暂停两处同步；在 Claude 插件页面移除 **Amh native org**，然后执行：

```bash
"$HOME/.local/bin/amh-native" uninstall
```

该命令恢复未被后续修改的配置并停用主客户端 LaunchAgent，**保留数据和软件**。出现 `conflicts` 时先核对后续编辑，不强行覆盖。完整重置登录、运行环境及残留 worker 是额外操作，需备份并核对范围；不要删除 `~/.codex`、`~/.claude` 或旧 AMH 记忆库。

升级须先停用旧 worker，再更新客户端和 Cowork 插件，不能仅覆盖磁盘软件。现有数据和身份保留；管理员按 [升级说明](upgrade-1.4.0.zh.md) 操作。首次安装者不需要执行升级流程。

## 十二、常见问题

| 现象 | 处理方式 |
| --- | --- |
| `Python 3.11+ required` | 安装受支持的 Python 后重开终端，再执行安装命令。 |
| 下载失败、404 | 核对本文地址并保留报错；不要改用不明来源脚本。 |
| `amh-native: command not found` | 使用本文的 `"$HOME/.local/bin/amh-native"` 完整路径。 |
| 飞书企业不符、无权限 | 核对当前企业，请管理员检查应用发布状态与可用范围，不发送密码。 |
| 授权完成但终端未成功 | 查看终端错误；超时后重跑向导，不复用旧回调地址。 |
| 历史选择页打不开 | 按终端提示处理；之后可用 `import --no-web` 改为终端选择。 |
| 待上传一直不下降 | 查看 `status` 的 `pending`、错误和暂停状态；后台按批次继续上传，`upload_deferred` 表示留队而非丢弃。请求与批次设置见[后台同步预算](dual-hub.zh.md#后台同步的请求与单轮预算)。手动 `sync` 仍尝试完整队列并显示具体错误。 |
| 云检索有结果，但产品未召回 | 新建会话；检查 Hook 启用/批准、提问相关性和超时。CLI 查询成功不能代替产品验收。 |
| 跨境或高延迟网络下组织召回总是超时（`hook-metrics.jsonl` 里 `mode` 为 `unavailable`、`elapsed_ms` 贴着 `budget_ms`） | 后台 worker 会保持到 Hub 的连接，每次召回只花一个往返（`via` 为 `service`）；仍不够就 `amh-native recall-timeout 3` 调大总预算（秒，默认 1.2，宿主 Hook 超时随之重写），然后新建会话让产品重新加载 Hook 配置。 |
| 想看每次召回调用了什么、召回了哪些记忆 | 默认每条提示后显示一张表：调用地址、查询摘要、产品/项目、检索方式（混合或仅词法）、耗时和预算，以及每条记忆的名次、来源、作者、版本、命中路由、相关度和本轮是否注入。「相关」是 Hub 估计这条记忆和你这句话相关的概率；1.4.9 起每次最多注入 3 条，同一笔记的多个副本只占一条，不相关的话题不注入（需要时让模型用组织检索工具主动查）。Claude Code 与 Cowork 以消息显示（框线表，按中文宽度对齐），Codex 显示在注入块里。`amh-native recall-display summary` 只显示一行，`off` 关闭。 |
| 想让召回像工具调用一样是彩色、可展开/收起的一行 | Claude Code 里装 mod：`amh-native claude-mod --output ~/.claude/amh-mods/amh-recall-view`，再用 `claude --plugin-dir ~/.claude/amh-mods/amh-recall-view` 启动（或把该目录加入 `CLAUDE_CODE_PLUGIN_DIRS`）。装上后每条提示下方是一行蓝色标题和摘要，点「展开」看调用、入参和表格。mod 没加载时自动回到普通消息。 |
| 「好的」「继续」「1」这类提示没有召回 | 有意为之：简短确认语没有可检索的主题，检索只会注入噪声。表格里会显示「跳过」及原因；带主题的短提示（如「灵鹤计划」）照常检索。 |
| 想知道本机召回整体表现 | `amh-native hook-stats --days 7`：跳过与原因、命中/注入次数、走常驻服务还是子进程、混合或词法、耗时 p50/p90。不含提示原文。 |
| Cowork 不生效 | 检查插件版本与启用状态、新建任务、核对独立运行时；CC 正常不代表 Cowork 正常。 |
| 说已记住但没有共享 | 确认实际写入位置、来源绑定及历史选择；产品可能延迟生成或限制写入。 |
| 需要换组织 | 独立状态目录重新登记，由管理员指导；不要直接改旧配置 URL 把旧队列发到新组织。 |

## 两个 Hub：独立同步，主 Hub 召回

客户端1.4.6支持按profile独立关闭召回、保持同步，以及只同步安装模式。迁移前须保留旧排除历史并审查新Hub的共享计划；操作顺序与Cowork边界见[双Hub说明](dual-hub.zh.md)。


### 按 Hub 独立控制上传和召回

用 `--state` 指定本机对应 Hub 的配置目录。下面以默认目录为例；其他 Hub 使用安装时选择的独立目录。

```sh
# 关闭召回，保留上传
amh-native recall --state ~/.amh-native-sync --disable
# 恢复召回
amh-native recall --state ~/.amh-native-sync --enable
# 暂停所有类型上传，保留召回；按提示确认
amh-native scope --state ~/.amh-native-sync --none
# 将上传范围设为仅长期记忆；按提示确认
amh-native scope --state ~/.amh-native-sync --kind memory
# 查看上传范围和召回状态
amh-native status --state ~/.amh-native-sync
```

`scope` 设置的是完整上传范围，不是增量开关。`memory` 指产品维护的长期记忆；其他类型是会话记录 `transcript`、规则 `rule`、技能 `skill`、配置 `config`。需要多个类型时重复 `--kind`。关闭上传保留选择、队列和云端内容，正在执行的一轮同步结束后生效。已有会话中的上下文不会因关闭召回而撤回，验证时请新建会话。
