# 1.3.2 评审修复与升级

本版修复身份、来源、云端模式、召回回流、首次安装与导入选择的一组边界问题。代码测试不能代替当前四端与生产数据验收。

## 成员行为

- 默认组织记忆只在云端检索。本机仅保存 AMH 同步所需的资产 ID、来源身份、版本及摘要证明，不保持其他成员的正文缓存。供应商自己的对话记录仍由供应商维护；AMH 不修改或删除这些会话。
- `setup --projection` 是显式保留本地原生组织副本的选择。未选择时，没有离线组织正文召回；网络预算耗尽就返回空结果。
- 勾选历史表示允许分享，不能证明本人创作。原作者无法确认时为“未知”，上传成员仍可追溯。与云端已验证完整版本相同的历史文件关联原来源，不虚增生产者。
- 选择器记录文件版本；用户确认前文件变化须重新选择。后续已选文件的正常更新仍按原同步机制处理。

## 管理员升级顺序

1. 停止将要升级的客户端 worker，防止仍加载旧代码的进程继续写入。保留本机原生目录与 outbox。
2. 对 Hub 数据库使用 SQLite backup API 生成一致性备份，并对备份运行 `PRAGMA integrity_check`。记录当前 release 软链、unit 和配置文件权限；密钥不进入日志或代码仓库。
3. 在独立目录安装候选 wheel 与已验证依赖，使用临时数据库完成登录/同步检查。不要原地覆盖正在运行的环境。
4. 核对旧部署的 **App ID 与飞书企业 tenant_key**。它们是不同标识；AMH 的 `linkcrux` 不是飞书 tenant_key。
5. 以具备该数据库权限的运维身份运行新版本迁移命令：

   ```bash
   /path/to/new/venv/bin/amh-native scope-feishu-identities \
     --db /var/lib/amh-native/hub.sqlite \
     --app-id cli_CONFIRMED_OLD_APP_ID \
     --tenant-key CONFIRMED_OLD_FEISHU_TENANT_KEY
   ```

   这是管理员对旧身份作用域的明确确认，不能凭姓名猜测。迁移为加表，不改变原成员/设备 ID、不复制设备令牌；同作用域重复执行安全，不同作用域或已有冲突则拒绝。旧映射表保留，以便审计与回滚。
6. 配置明确的企业白名单 `FEISHU_ALLOWED_TENANT_KEYS`，或管理页的单一企业标识。旧版已保存的企业 pin 可保留；新部署不能由首个公网访客决定企业归属。
7. 切换服务端 release 并验证 ready、登录可用性、原成员跨设备登录和组织边界。然后更新客户端/重新生成 Cowork 插件，重启 worker；进程必须加载新 wheel，不能只替换磁盘文件。
8. 对照前后清单验收：有效资产、删除状态、队列、原成员 ID、默认云端设备的 replica/recall_sources 中无共享正文。不要把某一轮零命中当成永久删除证明。

## 客户端缓存迁移

首次使用新版本时，策略迁移与同步使用同一 worker 锁。默认云端模式清除 `replica` / `recall_sources` 中的旧正文，保留不含正文的谱系元数据。只按拥有权清单和摘要删除未编辑的 `amh-org` 资源、移除已验证的导航块；不创建目录，不清空原生记忆，不触碰本机源快照和 outbox。用户修改过的文件保留，冲突写入本机 `storage-conflicts.json`，由用户决定如何处理。

这是应用层缓存清理，不承诺对磁盘历史快照或备份执行取证级擦除。

## 元数据复活与存量归属

`*.meta.json` 作为 transcript 元数据在新客户端枚举和 Hub 活跃写入两侧均被拒绝；墓碑仍可正常提交。新客户端会把已删除来源对应的过期活跃队列改回墓碑，并在增量回放发现本设备旧进程复活记录时重排删除。该修复不会删除其他成员或其他设备的资产。

此前被错误标为本人创作的存量内容不能仅凭文件位置自动纠正。应从修复前备份/选择记录形成精确资产清单，区分原始生产者和上传者，再进行有审计记录的更正。不要猜 base_revision，也不要把基准资产 ID 当分片 ID；当前 revision 必须来自权威记录。

## 回滚边界

保留旧 release、unit 与数据库备份。回滚前停止新旧 writer，并核对备份后的新增资产与撤权记录；不能直接覆盖生产库而丢弃新数据。新增身份和谱系表本身与旧 schema 共存，但回滚到 1.3.1 会恢复其已知来源/缓存缺陷，也可能再次允许旧元数据写入。因此不应把自动回滚到旧缺陷版本作为长期运行方案。

## 验证重点

回归包含双成员云端正文不落盘、原始生产者不被冒认、飞书同名/跨命名空间/显式迁移、历史文件变化、首次 projection、Markdown/JSONL 新旧注入边界、缓存策略切换竞争、用户编辑保留、错误摘要与跨分页分片完成证明，以及旧队列/旧服务写入后的墓碑收敛。
