# 召回与 Cowork 接入改进

本轮接续 `183a556` / `cb86bef` 的交底，复用 v1.3.1 已有基线，不重复原始测量。以下将候选实现与已运行版本分开记录。

## 召回实现与实测

- 在 Python 排序前给 memory/rule 2.5、skill 1.5 的权重；相关性仍来自 BM25，组织/项目可见性不变。
- 内部预算参数改名为 `max_bytes`，总 UTF-8 上限4096字节，包含Hook回执；最多5项，每项正文最多1536字节。不会让首个长会话耗尽全部预算，也不宣称这是精确token数。
- 来源展示通常保留姓名、产品与非空项目；原始ID/版本继续用于机器侧来源与覆盖判断。同名不同成员会附身份区分，不把两个人合并。未知作者仍与上传者分开。
- 每条截断内容使用固定配额，与剩余预算无关；覆盖键仍区分完整版本和具体片段，不把部分读取误记为全文读取。
- 单片直接验证已读取字节的摘要，免重复SQL；多片用表达式索引定位并流式校验完整内容。先排序，再仅校验实际需要返回的候选。
- 子进程召回边界1.2秒，网络边界1秒，安装的Hook硬限制仍为2秒。

## OpenAI 桌面实机结论

本机 `/Applications/ChatGPT.app` 的 bundle ID 是 `com.openai.codex`，版本 `26.1021.31345`。用户触发 `DESKTOP-HOOK-1102` 后，实际会话元数据表明 `originator=Codex Desktop`，紧接用户问题存在带 AMH 回执的 developer 注入。对应旧客户端日志为 `mode=cache`、约1065ms；回答引用到组织来源但未命中目标答案。

因此已验证的是 **该应用的本地 Codex 模式会执行当前用户级 Hooks**。安装器把共用入口标为 `codex-cli`，不能凭缺少 `chatgpt-desktop` 日志判定不支持。不要将此结论扩展到普通Chat或云端Work；[OpenAI Hooks文档](https://learn.chatgpt.com/docs/hooks)区分本地与云端编排支持范围。

## Cowork 接入

[Anthropic官方文档](https://support.claude.com/en/articles/13837440-use-plugins-in-claude)明确：Claude账号插件同步到Claude Code是单向的；CLI本地安装不能当作向Cowork账号安装插件的接口。账号插件支持Cowork Hooks，但当前可确认的自定义包接入路径是官方界面导入。没有向第三方私有目录写入插件或修改其manifest。

本机通过 Cowork 的官方 Show in Finder 入口核对了实际已安装插件：仍为 `0.1.0`，绑定旧隔离验收 Hub `127.0.0.1:65090` 和隔离测试状态目录。新生成的生产插件没有替换进去。因此本机连接失败不能只归因于票据过期；必须更新已安装插件，使其绑定正确Hub与本机持久状态。

改进后的安装流程：检测到Cowork后准备插件，仍在总体启用确认之后生成；macOS自动在Finder定位ZIP，打印官方导入说明。插件版本跟随AMH包版本，便于核对是否真正更新。

配对接口默认仍为15分钟；Cowork安装请求7天内可使用一次的票据，服务端限制60秒至7天。票据单独保存在0600私有连接文件中，不进入插件ZIP。赞助设备撤销会使未使用票据失效；已登记运行时继续使用独立设备身份。有效期延长会增加未使用票据的暴露窗口，不能等同于“安全性完全不变”。过期时重新运行 `cowork-connect`，不会把长期设备令牌复制到插件包。

## 验收边界

排序与正文送达、单/多片完整性、片段去重、同名身份、票据期限/单次使用/撤销及插件无凭证泄漏均有回归测试。OpenAI桌面本地Codex的Hook已实测；Cowork当前安装目标已查明。

发布前需同步升级Hub与本机客户端（旧Hub不接受新的票据期限字段），重启旧worker，再通过官方入口更新Cowork插件并完成新会话实机验收。不能把“ZIP已生成”写成“Cowork已接通”。
