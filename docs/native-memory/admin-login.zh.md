# 用飞书身份进入管理后台

适用于 Hub 1.4.2。管理员打开 `/native/v1/admin` 后自动进入飞书身份认证，授权成功且已具备 Hub 管理员角色时返回后台。数据看板 `/native/v1/admin/dashboard` 共享同一浏览器会话。

飞书可能要求首次授权或重新登录；能在飞书里打开应用不代表自动拥有 Hub 管理员权限。无权限的账号会收到明确提示。现有设备同步与召回继续使用自己的设备凭据，无需重装客户端。

## 首次配置

Hub 必须已有正确的飞书 App ID、Secret、公网 HTTPS 地址和允许登录的企业配置。沿用现有回调地址 `/native/v1/auth/feishu/callback`，无需新增回调路径或通讯录权限。应用主页指向 `/native/v1/admin` 即可。

后台权限必须由 Hub 主机管理员明确授予。先确认该成员已通过正常飞书登录加入组织，再在**加载了与 Hub 服务相同飞书配置的主机运维环境**中执行：

```bash
amh-native admin-role --db /var/lib/amh-native/hub.sqlite --member <稳定成员ID> --grant
```

命令核对当前应用及企业下已有的飞书账号绑定，不能用显示姓名或“第一个登录者”代替身份验证。多条匹配或未知成员会被拒绝。授予的管理员可以查看成员、设备、统计信息，撤销设备权限及修改飞书登录设置。

查看已配置的角色：

```bash
amh-native admin-role --db /var/lib/amh-native/hub.sqlite
```

撤销权限并立即作废该账号的后台会话：

```bash
amh-native admin-role --db /var/lib/amh-native/hub.sqlite --member <稳定成员ID> --revoke
```

角色撤销不会撤销该成员的设备凭据；设备访问在设备管理中独立撤销。

## 会话与恢复

后台会话有效期为 8 小时，退出会立即作废当前会话。会话凭据通过 Secure、HttpOnly、SameSite=Lax Cookie 保存，服务端只存凭据摘要；前端不读取凭据。变更操作同时校验来源和 CSRF，服务端每次请求重新核对角色。登录状态绑定当前浏览器、飞书应用与站点配置，过期、跨浏览器或重放回调会被拒绝。

页面的“主机管理员运维入口”保留原有管理令牌方式，供首次配置或飞书暂不可用时使用。选择飞书登录会清除当前页面中留存的运维令牌，不会把它当作飞书管理员身份。

本次新增 `admin_web_roles`、`admin_web_states`、`admin_web_sessions` 三张表，不改变既有成员、设备、记忆、变更序列或检索索引。旧版服务可忽略新增表；如需回退，切回旧版程序并恢复手动令牌入口，不恢复旧数据库覆盖上线后的同步数据。重新启用新版前应撤销此前的浏览器会话。

验证覆盖管理员/普通成员、应用与企业边界、同名账号、回调重放、浏览器绑定、CSRF、会话过期与撤销、旧管理令牌以及旧库加表。合成身份的浏览器验收不等同于真实飞书工作台验收，后者需在部署后用已授权账号完成。
